# Proposal: formalize the miniprojects tier

**Observation:** 2026-07-20, janhavi directly asked to add a new organisational tier — `miniprojects/`, sitting alongside `projects/` — for tiny candidate projects she isn't sure enough about yet to commit to full-project ceremony. Implemented live in `bismuth-memory/miniprojects/` (summary.md + miniprojects_list.md + first entry `shubhamsPlot`), designed under the latitude the Memory Structure Protocol already grants Bismuth to add new structural elements. Not yet reflected in the protocol files themselves, so a fresh session reading only protocols (not memory) wouldn't know this tier exists as a named concept.

**Suggested wording:**

- Add to `01_memory_structure_protocol.md` (Basics): alongside `projects/`, home folder may have a `miniprojects/` folder — lighter-weight candidates for projects. Each miniproject folder has `summary.md` + `notes.md` only (no mood/vision/nexttodo/coffeechat/reference by default); `reference/` added only on demand.
- Add to `13_project_creation_protocol.md` (or a short new section): a promotion ritual — moving a folder from `miniprojects/<name>/` to `projects/<name>/`, scaffolding up to full structure, folding `notes.md` into `vision.md`/`nexttodo.md`, updating both list files.

Small enough to fold into either existing file; doesn't need a standalone protocol.
