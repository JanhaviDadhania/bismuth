Bismuth v2 — Architecture

phone → main agent (no tools) → intents → workers → memory. Click/expand boxes for detail. 100% drag to pan · scroll/pinch to zoom · click ▸ to expand

👤 Her (Janhavi)

Speaks into her phone. Only channel in/out. Only the main agent's voice reaches her.

📝 Notes / turn input

Telegram voice/text note → STT → one of three labelled turn inputs, exactly one per turn: NOTE · SUBAGENT_RESULT · SYSTEM
Expand: turn-input blocks (exact text injected every turn)

The runtime assembles a single text blob per turn from labelled blocks (v2/mainagent.py: build_turn_input):

  • DESTINATIONS — the full memory tree + which folders carry a CLAUDE.md (* marker). ~3.2k tokens. Sent only on a new session or when the tree's fingerprint changes (not every turn).
  • TOOLS — index of what a worker's Bash can reach, read from ~/bismuth-memory/_tools/*.md cards. Rides the same fingerprint gate as DESTINATIONS.
  • TASKS — the full live task list (unclear / working), sent every turn — this is what makes the session disposable.
  • RECENT — last DONE_TAIL = 5 completed tasks, one line each (config: done_tail).
  • OTHERS — what's currently parked in others/, with a count.
  • Then exactly one of: NOTE (from her, transcribed), SUBAGENT_RESULT (a worker finished — "she has not seen this"), or SYSTEM (a schedule fired or went overdue — "she has not seen this").

🧠 Main agent — --tools ""

claude -p, one continuing session, one turn at a time, serialized. It decides, it never does. With no tools it cannot read/write/run anything — enforced by the CLI flag, not a prompt convention. Output: a single JSON object validated by --json-schema intent_schema.json.
Expand: the turn queue & serialization
One serialized queue (state.json: turn_queue) holds both incoming notes and finished sub-agent results, in arrival order — one queue, one turn at a time, whichever the source. A sub-agent's terminal result is enqueued durably before its process is reaped — that write is the commit point; lose it and the result never reaches the agent and its task hangs in working forever (the one tier-1 state with no rebuild path).

Scheduled work (_schedules/*.md, see the Schedules box below) also enters this same queue as a SYSTEM item and does not preempt — "08:30" means "the next free slot after 08:30."
Expand: session lifecycle & the auto-reset mechanism

One continuing claude -p session, resumed via --session-id (new) / --resume <id> (continuing). Session state lives in tier-1 state.json: session = {id, started_at, window_size, tokens, turns}.

Hard, automatic reset — no judgement call — once the session's cumulative token count (measured from claude -p's own result.usage on every turn, not estimated from characters) reaches a threshold of the model's context window:

ConstantValue (today, 2026-10-02)Where
CONTEXT_WINDOW200,000 tokens (default)v2/config.py — v2.context_window in config.yaml
RESET_PCT0.60 (60%)v2/config.py — v2.reset_pct
Reset fires at200,000 × 0.60 = 120,000 tokensmainagent.needs_reset()

Checked after every turn in runtime.process_turn() via mainagent.needs_reset(session); the comparison is session.tokens >= window_size * RESET_PCT. The running total is the sum of input_tokens + cache_creation_input_tokens + cache_read_input_tokens + output_tokens from the final result event of the subprocess stream.

Trace event on reset: session_reset with reason: "requested" | "context_40pct" (the event name/reason string is a holdover from an earlier 40% design value in the architecture doc — the code constant is now 0.60/60%).

Session reset on request: she can say "reset the session when you're done" → session_reset intent → reset_requested=True → deferred until every spawned worker for the current note has settled (pending_reset_ids empties out), then the session is dropped in runtime._maybe_reset().

Because TASKS is resent every turn (see above), a reset loses no open work — nothing load-bearing lives inside the model's own context.

Other main-agent numeric constants (v2/config.py):

  • MAIN_AGENT_TIMEOUT = 600s (subprocess.Popen timeout for one turn)
  • DONE_TAIL = 5 (RECENT block size)
  • ACK_TAIL = 10 (board's ack strip size)

Output is {"intents": [...]}", validated against prompts/v2/intent_schema.json, performed by the runtime (v2/intents.py: Executor) in listed order — one trace event per intent. Ten valid types (VALID_TYPES in intents.py):

Expand: routing & the DESTINATIONS guard

The one hard guard: the destination must already exist. A tool-less agent can't check a path itself, so the runtime injects the real memory tree every gated turn (v2/destinations.py: render()), with a * marking folders that carry a CLAUDE.md. destinations.resolve() re-checks the agent's chosen path against the real filesystem — if it names something that isn't real, the route is rejected (route_rejected trace event) and the note is parked in others/ instead (park-first, then ask).

Scan skips reserved/machine-owned dirs: .git, .harness, __pycache__, node_modules, .obsidian, trace, .bismuth, .venv, anything starting with _ or ., and anything deeper than MAX_DEPTH = 4.

⚙️ Intents → Executor

v2/intents.py. The runtime performs the agent's intents and writes a trace event for each — the agent never touches disk itself.
Expand: what runtime does itself (not delegated)
Two things the runtime performs directly, never via a worker:
  • parking a note in others/ — must be atomic, can't depend on a worker succeeding
  • sending Telegram messages — the agent has no tools, so every word she reads is text the runtime carries for it
Everything else (file writes, searches, tool investigation, installs) is a spawn or route intent → a worker subprocess.

📱 Reply → Telegram

Text, voice (macOS say → ogg via ffmpeg → sendVoice), images, docs, links. Only the main agent's voice. Quiet by default — acks live on the board, not pushed to her.

🛠️ Sub-agent (worker)

claude -p subprocess, stripped bare. No identity, no skills, no MCP, no memory of anything else. Receives one self-contained instruction and nothing else.
Expand: the four tools
SUBAGENT_TOOLS = "Read,Write,Edit,Bash" (v2/config.py).
  • Read, Write, Edit — the memory writes, the whole job. Prefer Read+Edit over shelling out.
  • Bash — the terminal; most expensive schema, and the one that lets a worker wander, kept anyway for reach (e.g. silicon-browser as a plain command).

Measured cost of choosing Bash for a one-line file append vs Read+Edit: 118,011 tokens / $0.37 vs 8,092 tokens / $0.024 — 15× cheaper, both correct.

TOOLS block: beyond the fixed four, a worker's Bash can reach anything named in ~/bismuth-memory/_tools/*.md cards (e.g. silicon-browser). The main agent gets only the index (name + one-line summary + card path); the worker reads the card itself for the real command surface.

Expand: terminal statuses (the entire protocol)
A worker ends in exactly one of three states — its final message is required to be a single JSON object, e.g. {"status":"done","summary":"..."}:
statusmeaningwhat main agent does
donework finished and self-verified (read-back)closes subtask; tells her when the whole task is complete
needs_inputcan't proceed without her answertask → back to unclear; she's asked; a fresh worker is spawned later (nothing is resumed — workers are stateless)
failedit broketells her, with the error

A worker never messages her — no channel, no polling, no waiting. It exits; its return value is read by the main agent on a later turn via a SUBAGENT_RESULT block.

🗂️ ~/bismuth-memory

Markdown in git. projects/, miniprojects/, root files, reference/, others/ (parking folder), plus machine-owned _-prefixed folders invisible to routing.
Expand: reserved machine folders & CLAUDE.md
  • _schedules/*.md — one file per recurring job; see Schedules box
  • _tools/*.md — one card per installed tool a worker's Bash can reach
  • others/ — park-first-then-ask folder for unroutable notes; visible on the board with a count
  • 5 per-folder CLAUDE.md files (~10.6 KB) — folder-local context; a stripped worker doesn't auto-discover these, so the main agent must name the path (or inline the key lines) in the instruction

🖥️ board.html

Regenerated from the memory tree + trace by tools/board.py every BOARD_REFRESH_INTERVAL = 120s. Shows Tasks (NEEDS YOU / WORKING), others/ count, and a secondary ack/recently-done strip. Holds no state of its own.

🔁 Turn queue (state.json)

One serialized queue, notes and sub-agent results and schedule firings, in arrival order. Tier-1 authoritative state — the one piece with no rebuild path.
Expand: retry queue & dedup ledger

Retry queue (state.py: queue_retry / take_retries): a turn that errors out (mainagent.run_turn returns error) is never silently dead-lettered. runtime._turn_failed() appends a turn_failed trace event, pushes {item, error, at} onto state.json: retry, and tells her over Telegram that the note is safe and queued for retry. This is the direct fix for v1's 113-entry silent dead_letter/.

Dedup ledger (processed_ids): keyed on Telegram's update_id, caps at PROCESSED_IDS_KEEP = 5000 entries, makes redelivery (e.g. after a crash before the offset advanced) a no-op.

Offset: getUpdates offset only advances after a message is durably spooled to disk — the spool write is the commit point, not the Telegram ack.

⏰ Schedules (_schedules/*.md)

Recurring work on a clock — a markdown file, not Python. Created/edited only via schedule_create / schedule_update intents (runtime writes them, never a worker — short structured data that must not fail).
Expand: frontmatter fields & tick mechanism 
---
every: daily      # daily | weekly | N_days
at: "08:30"
days: [sun]        # weekly only
enabled: true
budget_usd: 4.00
produces: projects/x/{date}.txt
min_bytes: 500
summary: morning digest
---
Scroll x.com and write the digest to {MEMORY}/…/{date}.txt.

Background loop checks every SCHEDULE_TICK_INTERVAL = 60s. tick() fires what's due (date-guard, not interval — "08:30" means next free slot after, not every 60s), enqueuing a SYSTEM turn item that names the file as the contract (never paraphrased).

check_overdue() asks, independent of what the worker claimed, whether the promised produces: artifact actually landed and is ≥ min_bytes, SCHEDULE_OVERDUE_AFTER = 2 × 3600s (2h) after firing. A worker returning done is not evidence — this catches "worker lied", "worker failed", and "main agent decided not to spawn anything at all."

🗒️ Trace (append-only JSONL)

~/bismuth-memory/trace/log-YYYY-MM.jsonl. Single source of truth — board and task list are projections of it, never separate files that can drift. Never rotated.
Expand: event fields & ordering

Every event carries ts (ISO 8601 + offset), seq (global, gapless, monotonic — the authoritative sort key, assigned under the append lock; a gap in seq means an event was lost), and trace_id (Telegram's update_id, joins every event for one note).

TRACE_EVENT_CAP = 8,000 chars per field — the only thing bounding trace growth since there's no rotation (one tool result can be an entire file read).

Event types include: note_received, stt_done, route_decided, route_rejected, memory_written, parked_in_others, task_created, task_question_asked, task_clarified, task_blocked, task_done, subagent_spawned, subagent_event, subagent_done, subagent_failed, agent_event, turn_usage, session_started, session_reset, reply_sent, reply_failed, ack, turn_failed, retry_queued, schedule_created, schedule_updated, schedule_fired, schedule_overdue, schedule_parse_failed, runtime_started, boot_reconciled, background_check_failed, loop_error, runtime_stopped.
